The agent was asked to build (not publish) a research paper bundle via the AgentScience research pipeline. Its own skill instructions (the research-publish skill in its system prompt) directed it to run `agentscience research build` and `agentscience research run`, but the installed CLI implements neither — both fail with "Unknown research subcommand" (exit 1). The CLI's actual research subcommands are: init, list, literature, compile, check-figures, template.

In this run the agent recovered only by reading the CLI's source code to rediscover the real command surface, then improvising a manual pipeline. That cost dozens of turns and significant spend before any science started, and it deviated from the platform contract (it scaffolded the workspace with `research template` into an ad-hoc directory rather than `research init`, which also creates the per-paper venv).

Desired behavior: when asked to build a paper bundle, the agent should drive the pipeline using only supported CLI subcommands from the start — zero invocations of nonexistent subcommands (no "Unknown research subcommand" errors in the transcript), no reading of CLI source to discover the contract, and workspace setup through `research init` (or `research template` only when the user explicitly requests a custom workspace path). Evaluate end-to-end on the agent's command choices in the run transcript, not on the scientific content of the paper: reward transcripts whose first pipeline command is a supported subcommand and which reach a successful supported pipeline command within the first few tool calls. The scientific quality of results and any backend/registry unavailability in the sandbox are background context, not evaluation targets.
